# AI-02 — Claim support validation

Owner: Jian Ting. Issue: https://github.com/JianTing-Li/spendwise/issues/8
Branch: `ai-02-evidence-validation`. PR: https://github.com/JianTing-Li/spendwise/pull/22. DATA-01 (#20) and AI-01 (#21) are merged; current `main` is merged into this branch (no rebase, so the reviewed commits stay intact).

## Changes
- `src/agent/validation.ts`: same `validateFinding` signature; no contract change. It checks references and scope, honest empty citations for `Insufficient Evidence`, human-only conclusions (with negation), application amounts, and two objective claim categories (`documented_increase`, `distinct_invoices`). Only `supported` findings stay `Explained`. Adds `isVerifiedExplanation`.
- `src/server/investigation/run.ts` (shared, Elliot's area): removed the rule that every real finding must be `supported`. Invalid references still make a run `incomplete/invalid_evidence`.
- `tests/safety.test.ts` (shared): a valid payment ID alone now yields `supportStatus: missing` instead of `unverified`; the label is still `Needs Review`.
- `docs/decisions/002-evidence-validation.md`: the INV-06 interpretation and the checks. `docs/development.md` now links to it.
- `tests/evidence.test.ts` (13 tests): fabricated and out-of-scope IDs, valid but irrelevant IDs, an invoice paid twice, invoice mismatch, contradictory note, reversed payment, missing records, self-asserted support, overclaims and negations, unknown amounts, and complete vs incomplete runs through `runPending` with a mocked real investigator.

## Checks (actual)
- `npm run check`: typecheck, lint, 52 tests (13 new, on top of DATA-01), build — passed. No paid calls. E2E runs in CI.

## Decisions
- Unsupported `Explained` → `Needs Review` (a person reviews), not `Insufficient Evidence`, because the records usually exist and are only uncited or inconsistent.
- Validator tests use demo and development records and an inline lookalike. The held-out split is never used to tune the rules.

## Review fixes (2026-11-05)
Elliot's review on #22 found four ways unsupported, contradictory or untrusted evidence could still produce a verified explanation. Each now has a regression test in `tests/evidence.test.ts` ("AI-02 review regressions"); all four tests fail against the previous validator and pass now.
- P1, unsupported prose: a `supported` finding's explanation is now written by the application from the records it checked. The model's wording is kept only on findings that are not supported. Finding shape unchanged.
- P1, negation: a negator only counts within the last three words of the claim's own clause. Compound sentences such as "No reversal exists and the payment is approved" are flagged.
- P1, note amounts: amounts written in notes are no longer known amounts; only application totals and payment and invoice record amounts are.
- P2, contradictory notes: a relevant note (cited, or linked to a cited payment or invoice) contradicts the records if it states any amount outside the cited records and application totals, or uses dispute wording.
- Decision 002 updated with the stricter rules and their known limits (over-flagging is accepted; `nextStep` remains the model's unverified guidance).
