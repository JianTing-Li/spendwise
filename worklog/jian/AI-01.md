# AI-01 — Bounded Claude investigator

Owner: Jian Ting. Issue: https://github.com/JianTing-Li/spendwise/issues/7
Branch: `ai-01-claude-loop`, from `origin/main` at `7c4306b`.

## Changes
- `src/agent/loop.ts`: `createRealInvestigator`, one explicit tool-calling loop on the official SDK (`messages.create`, non-streaming).
  - Every model request and every attempted retrieval is charged to `Budget` before it runs. That includes unknown tools, invalid input and failures; the limits are 8 retrievals and 10 requests.
  - SDK `maxRetries: 0` on the client and on every request. Each request's `timeout` is the time left.
  - The loop stops 10 s (`VALIDATION_RESERVE_MS`) before `deadlineAt`, using an internal `AbortController` linked to the caller's signal. The deadline is checked in code before each request and retrieval; it does not rely on the prompt or `Promise.race`.
  - Structured output arrives through a `submit_findings` tool and is validated with Zod (1–5 findings). Malformed submissions get an error result and may be corrected within the request budget. The application sets exception ID, `referenceStatus: unchecked` and `supportStatus: unverified`; model-supplied values are dropped.
  - Retrieved records go back as `{"untrusted_records": …}`, schema-checked and capped at 60k characters. The tool list is fixed; unknown tools and keys outside the strict input schemas (for example `sql`) are rejected.
  - Outcomes: `completed`; `incomplete`/`unavailable` after a retrieval failure; `incomplete`/`tool_limit`, `model_limit` or `deadline`; `cancelled` when the caller aborts first; `failed`/`unavailable` for API errors and refusals; `failed`/`internal` for missing or truncated output. An incomplete run never keeps an `Explained` label. There is no stub fallback.
  - `onRequest` telemetry: served model, requested model, stop reason, latency and tokens, for FEAS-01/EVAL-01.
- `src/agent/client.ts`: `realInvestigatorFromEnv` builds the SDK client lazily from server-side env (`ANTHROPIC_MODEL`, default `claude-opus-5-5`, effort `medium`).
- `src/agent/prompt.ts`: system prompt adapted from PRD v0, versioned `prompt-v1`. `src/agent/tools.ts`: the model tool list and submission schema, generated from the shared contracts.
- `tests/agent.test.ts`: 13 fake-response tests. They cover valid output, parallel calls, malformed then corrected output, no output, retrieval failure, hostile text with unknown and out-of-scope calls, the 8-retrieval limit, the 10-request limit, the reserved deadline, cancellation mid-request, API error, refusal and truncation, and the tool allowlist.

## Checks (actual)
- `npm run check`: typecheck, lint, 37 tests (13 new), build — passed. No live or paid model call was made.

## Interface decisions
- Module split: `real.ts` (the app's entry point, no SDK), `loop.ts` (loop, SDK types only), `client.ts` (SDK client). The first CI E2E run failed because the dev-server's first compile of `/api/demo` took more than 5 s once the route pulled in the SDK. Rerun and split recorded in the PR.
- No contract change. The real loop gets retrieval through a `retrievalFor(input)` factory option, not through the shared `Investigator` interface.
- `realInvestigator` (used by `src/server/investigation/run.ts`) still returns `failed/unavailable`. Wiring `realInvestigatorFromEnv(retrievalFor)` to database-scoped retrieval is INT-01's job, so real mode never runs a model without application-scoped retrieval.
- Server-side refusal fallback to another model is deliberately not enabled: a run must record exactly which model produced it, and the project forbids silent fallbacks. A refusal is a visible `failed` run.
