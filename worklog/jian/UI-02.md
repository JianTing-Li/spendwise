# UI-02 — Dashboard layout, accessibility and finance-copy fixes from design audits

Owner: Jian Ting. Reviewer: Elliot Watson (`src/app/` owner).
Issue: https://github.com/JianTing-Li/spendwise/issues/48
Branch: `ui-02-dashboard-polish`, from `origin/main` at `d6ab7a9`.

## Changes
- `src/app/globals.css`:
  - Removed `@import "tailwindcss";` so Tailwind Preflight no longer strips margins and list bullets inside finding cards. Added explicit spacing rules inside `.finding` and `list-style: disc` on `.evidence-links`.
  - Added margin and padding to `.run-status` so its `3px` focus outline does not overlap adjacent lines.
  - Styled `.header-actions` for the header sign-out form and `.access-required` so the access-required fallback matches the dashboard header, spacing and typography.
  - Changed the `.queue` single-column breakpoint from `760px` to `900px` so `768px` renders a single full-width column instead of two narrow `334px` columns.
  - Stacked the vendor payment table below `640px` using `data-label` attributes so September, October and Change remain readable at `375px` and `390px` without horizontal scroll or clipping.
  - Darkened `--muted` from `#63726e` to `#52615d`, darkened focus outline `--focus` from `#bd8725` to `#9a6b15`, darkened `.rule` (`#73501c`) and `.tag` (`#664918`), and raised all sub-12px font sizes (`.rule`, `th`, `.tag`, `.eyebrow`, `.environment`, `footer`, `.record-id`) to at least `12px`.
  - Added monospace styling (`.record-id`) for record IDs in citations and source records, `44px` minimum height on `<summary>` controls, distinct sentence-case `.state-*` styles with border treatments for all six run states, right-aligned tabular figures (`.num`, `.cash-comparison`, `.metrics strong`), regular-weight `<small>` inside `dd`, and receded `.finding.reviewed` card styling.
  - Aligned `.reset-confirm` as a single-line inline bar matching the primary button height (`min-height: 49px`), pinned card disclosures (`.finding-disclosures`) to the bottom of `.finding` while setting `.queue:has(details[open]) { align-items: start; }` so expanding one card's disclosures does not stretch its neighbor, and added `fadeSlideIn` transitions on cards, empty state, reset confirmation and `details[open]` children (respecting `prefers-reduced-motion: reduce`).
- `src/app/page.tsx`:
  - Moved the sign-out form into `<Dashboard>`'s `<header>` as a secondary button (`canSignOut`), and updated the access-required fallback to use the dashboard `<header>` and `.access-required` layout instead of `<main className="p-8">`.
- `src/app/dashboard.tsx`:
  - Moved the Investigation queue section above the Vendor payments table, and sorted the queue by `summary.differenceCents` descending so Northstar Software (`+$12,000.00`) leads and the two Harbor Advisory cards sit adjacent.
  - Replaced the hero slogan and lede with a single-line `22px` title (`Vendor payment exceptions · October 2026`) and clean business name eyebrow (`Ledner LLC` derived from `businessName`), keeping `"Synthetic data"` once in the top-right header badge and removing the prototype footer to match the PRD Product Sketch.
  - Replaced the `"October cash paid"` overview tile with an always-mounted `.status-strip` (`role="status"`, `min-height: 44px`) that shows the comparison range and October cash total when idle, and shows progress or reset messages in place without layout shift.
  - Added inline confirmation before Reset (`"Clear N findings and M reviews?"` with `Confirm reset` and `Cancel`) whenever scenario state is present, and dimmed `.dashboard-body` during reset instead of collapsing the page.
  - Updated the Human review tile to display `"X of Y reviewed"` and include failed run counts (e.g. `"0 of 4 reviewed · 4 failed"` when all runs fail).
  - Updated the public read-only and unauthorized banners to state that viewers can open citations and source records while Simulate, Reset, Retry and Mark reviewed require sign-in.
  - Replaced `"Scenario injected"` with `"Payments added"`, replaced the queue subtitle with live exception/review counts (`"4 exceptions · 0 reviewed"`), and replaced the empty-state copy with `"Adds three October scenarios: one large increase and two pairs of same-amount payments."` without the `✓` glyph.
- `src/app/review-card.tsx`:
  - Updated `possible_duplicate` cards to lead with `"Amount in question: $3,000.00, not confirmed"` (computed for display from `dataset.payments` for `exception.paymentIds`) and list both flagged payments with ID, short date, invoice number and amount instead of leading with the vendor's `$6,000.00` monthly total.
  - Added context beside each citation link (e.g. `payment: pay-advisory-a · Oct 8 · $3,000.00 · invoice HA-101`) while keeping the `<a>`'s accessible name starting with `type: id`.
  - Cross-linked cards that share a vendor (`"Also flagged for this vendor: Possible duplicate"` / `"Payment increase"`).
  - Moved the attempt/retrieval/model-request counters and run ID / generation into a `<details className="run-details">` (`"Run details"`) disclosure.
  - Removed repeated unverified fine print from the card face, keeping one support badge next to the finding label (`"Records match · application check"` or `"Draft · explanation not verified"`) and one acknowledgment caveat at the `Mark reviewed` button (`"Records that you looked at this finding. It does not approve the payment."`).
  - Split `unavailable` run errors into a not-configured message (`"Real model is not configured in this environment. Retrying will not help."` when `mode === "real"` and zero lookups/requests were made) and a records-unreadable message (`"Evidence records could not be read during the investigation. Try again."`).
  - Placed the run error and `"No findings were saved."` before a secondary-styled Retry button, changed the zero-call real-mode tag to `"Real mode · no model call made"`, and updated the exhausted-retries text to `"All 3 attempts failed. Review the source records below, or reset the demo to clear every finding and review."`
  - Changed `status.current?.focus()` to `status.current?.focus({ preventScroll: true })`, made vendor headings `<h3>` under the queue `<h2>`, and added `aria-label` to focusable `.record` elements.
- `src/app/format.ts`:
  - Added `percent(value)` for signed, grouped percentages (`"+1,200.0%"`) and `"n/a (prior is $0.00)"` when prior cash is zero, plus `shortDate(isoDate)` for UTC short dates (`"Oct 8"`).
- `tests/e2e/demo.spec.ts`, `tests/e2e/retry.spec.ts`, `tests/e2e/review.spec.ts`:
  - Updated locators to match the new copy, sentence-case state badges, queue ordering, `Run details` disclosure, and inline Reset confirmation while preserving all assertions on honest run states, unverified badges, focus movement and zero horizontal scroll.

## Decisions
- Replaced the `"October cash paid"` metric tile with the always-mounted `.status-strip` above the overview tiles (`"Sep 1–30 vs Oct 1–31, 2026 · October cash paid $22,000.00 (completed payments net of reversals)"`). This removes a redundant third tile while giving live progress and reset status messages a reserved `44px` slot so stub runs do not shift the page vertically.
- Kept `"Reset demo"` immediate when the dashboard is already at the empty baseline (`!hasScenarioState`) and required inline confirmation (`"Clear N findings and M reviews?"`) whenever scenario exceptions, runs or active injections exist.
- Distinguished the two `unavailable` failure causes in `ReviewCard` using existing `Run` fields (`run.mode === "real" && run.modelRequests === 0 && run.toolExecutions === 0` for missing model configuration vs retrieval failure after activity), avoiding any contract or server change.
